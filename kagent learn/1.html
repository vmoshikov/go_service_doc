In this lab, you will create your first AI agent using kagent. kagent is an open-source framework that brings the power of agentic AI to cloud-native environments.

We'll start by downloading and installing the kagent binary. Run the following command to download and install kagent CLI:

bash
curl https://raw.githubusercontent.com/kagent-dev/kagent/refs/heads/main/scripts/get-kagent | bash -s -- --version v0.1.11

Kagent CLI features a REPL environment that allows you to install kagent onto your cluster and interact/chat with the agent running in the cluster.

Before we continue, make sure you set the OPENAI_API_KEY environment variable with your OpenAI API key. This is required for the agent to work properly. You can set the environment variable by running the following command:

bash
export OPENAI_API_KEY=<your-openai-api-key>

Let's start the REPL environment by running the kagent command:

bash
kagent

Next, run the install command to install the kagent into the cluster:

bash
install

Once the installation is complete, you should see a message indicating that the kagent has been installed successfully.

Let's check the cluster to see what's installed - first exit the CLI:

bash
exit

Then list the pods in the kagent namespace:

bash
kubectl get po -n kagent

As you've seen earlier, kagent comes with a couple of pre-created agents for you to use. However, in this lab we'll create a new agent from scratch.

We'll create an agent using YAML and apply it to the cluster:

shell
kubectl apply -f - <<EOF
apiVersion: kagent.dev/v1alpha1
kind: Agent
metadata:
  name: my-first-agent
  namespace: kagent
spec:
  description: This agent can interact with the Kubernetes API to get information about the cluster.
  modelConfigRef: default-model-config
  systemMessage: |-
    You're a friendly and helpful agent that uses Kubernetes tools to answer users questions about the cluster.

    # Instructions

    - If user question is unclear, ask for clarification before running any tools
    - Always be helpful and friendly
    - If you don't know how to answer the question DO NOT make things up
      respond with "Sorry, I don't know how to answer that" and ask the user to further clarify the question

    # Response format
    - ALWAYS format your response as Markdown
    - Your response will include a summary of actions you took and an explanation of the result
  tools:
    - provider: kagent.tools.k8s.GetAvailableAPIResources
    - provider: kagent.tools.k8s.GetResources
EOF

This agent uses two Kubernetes tools to interact with the cluster. Tools are the other building block of the agent. They are the commands that the agent can run to interact with the environment. As LLMs don't have the ability to run commands, tools are the way to bridge the gap between the agent and the environment. Kagent provides a set of built-in tools that you can use to interact with Kubernetes, Istio, Prometheus and projects. You can also build your own tools and connect existing tools using MCP (Model Context Protocol).

For this agent, we'll add the following tools two tools - GetResources and GetAvailableAPIResources. The first tool allows the agent to run kubectl get command and retrieve resources running in the cluster. The second tool allows the agent to get a list of available API resources in the cluster.
