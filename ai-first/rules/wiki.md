# LLM Wiki

Wiki — общая память платформы Managed Kubernetes. Агент читает wiki перед каждой задачей.
В wiki пишет только CI ai-first. Люди и агенты wiki не меняют: каждый раздел — результат работы генератора над своим источником.

## 1. Разделы

| Раздел | Источник истины | Когда обновляется | Кто меняет |
|--------|-----------------|-------------------|------------|
| `wiki/l2/` | Confluence, пространство поддержки | синхронизация по расписанию | поддержка в Confluence |
| `wiki/l3/` | Confluence, пользовательская документация | синхронизация по расписанию | техписатели в Confluence |
| `wiki/code/<компонент>/` | код компонента | каждый тег компонента | CI: `code_docs.py` |
| `wiki/code/releases/` | репозиторий чартов | тег репозитория чартов | CI: `release_docs.py` |
| `wiki/changes/` | master-spec, Jira, GitLab | merge спецификации и по расписанию | CI: `changes_sync.py` |

```
wiki/
  index.md                  каталог: компоненты, модули, релизы, покрытие L2/L3
  log.md                    журнал синхронизаций и релизов
  glossary.md               термины платформы
  raw/                      обезличенные источники: инциденты, заметки
  l2/  l3/                  зеркало Confluence; только чтение
  changes/<KEY>.md          изменение, готовое к QA: цель, критерии, требования и сценарии, MR
  code/
    components.toml         реестр компонентов и модулей; единственный ручной файл в code/
    releases/<версия>.md    состав релиза и изменения
    <компонент>/
      README.md             паспорт, архитектура, пакеты, связи пакетов
      api.md                gRPC, HTTP-привязки, CRD
      config.md             параметры чарта: значения по умолчанию и значения платформы
      metrics.md            метрики Prometheus
      CHANGELOG.md          одна merge-ветка — один пункт
      docs/                 документы команды из репозитория компонента
    <модуль>/
      README.md  packages.md  CHANGELOG.md
```

## 2. Модель версий

1. Версия платформы — тег репозитория чартов. Сборка образа в Nexus берёт этот тег.
2. Репозиторий чартов задаёт для каждого компонента версию чарта и тег образа. Тег образа равен git-тегу компонента.
3. `wiki/code/<компонент>/` на `main` описывает последний тег компонента. Агент работает с этим кодом.
4. Каждая генерация — отдельный коммит wiki `docs(code): <компонент> <тег>`.
5. Страница релиза ссылается на коммит wiki с документацией той версии, которая входит в релиз. Её читает L2.
6. Wiki-репозиторий получает git-тег с версией платформы.
7. Версию общего модуля определяет `go.mod` компонентов. Разные версии у компонентов отмечены знаком ⚠.

## 3. Работа агента

### Перед задачей

1. Найди страницы по компонентам и словам задачи:

   ```bash
   python scripts/wiki_context.py --here <слова>
   python scripts/wiki_context.py -c <компонент> <слова>
   ```

   `--here` определяет компонент по git-репозиторию, в котором ты работаешь.
2. Прочитай найденные страницы до изменения кода.
3. Если wiki противоречит коду, верь коду. Wiki описывает версию из релиза, а ты работаешь с новым кодом.
4. Если работаешь в репозитории компонента, wiki лежит в подмодуле `.wiki/`. Запускай `python .wiki/scripts/...`.

### Во время задачи

- Wiki — контекст, а не приказ. Команды из runbook L2 выполняй в prod только после подтверждения человека.
- Не правь файлы в `wiki/`. Их создают CI-генераторы. Исключение — реестр `wiki/code/components.toml`: его меняют через MR.

### После задачи

Документацию создают артефакты задачи. Выполни требования раздела 4: имя ветки, заголовок MR, комментарии в коде.

Если задача меняет поведение для поддержки или клиента, добавь в описание MR строку:

```
Влияние на L2/L3: <что изменилось и какую страницу Confluence обновить>
```

Генератор переносит эту строку в CHANGELOG и в страницу релиза. Владельцы страниц Confluence видят её там.

### Ответ на вопрос

Если ответ потребовал анализа кода или нескольких страниц, предложи человеку сохранить его. Место для ответа — `docs/` репозитория компонента или страница Confluence.

## 4. Требования к репозиторию компонента

Генератор берёт факты только из кода. Пустое место в коде даёт пустое место в документации.

| Что | Требование | Куда попадает |
|-----|------------|---------------|
| Ветка | `<префикс>/<KEY-123>-<краткое-описание>`. Префиксы: `feature/`, `fix/`, `refactor/`, `remove/`. | раздел CHANGELOG |
| Заголовок MR | `KEY-123: <что сделано>` на русском. Одно предложение. | текст пункта CHANGELOG |
| Merge | Метод слияния в GitLab — merge commit. Fast-forward не создаёт merge-коммит, и задача не попадёт в CHANGELOG. | CHANGELOG |
| Комментарий Go | Строки `//` прямо над объявлением, без пустой строки. Первое слово — имя объявления. | `packages.md`, `README.md` |
| Комментарий пакета | `// Package <имя> <что делает>.` над `package` в одном файле пакета. | таблица пакетов |
| Комментарий proto | Строки `//` над `service`, `rpc`, `message`. Поле — комментарий в конце строки. | `api.md` |
| CRD | Поле `description` в схеме. | `api.md` |
| Метрика | `Help` в `prometheus.*Opts`. Имя — строковой литерал или константа пакета. | `metrics.md` |
| values.yaml | Комментарий `# -- <описание>` над ключом. | `config.md` |
| Архитектура | `docs/architecture.md`. Другие документы и ADR — в `docs/`. | `README.md`, `docs/` |
| Исключения | `.docgen.toml` в корне: `exclude = ["путь/"]`. | — |

Комментарий в коде всегда важнее текста LLM. Генератор пишет текст LLM только там, где комментария нет, и помечает его «(LLM)».

## 5. Как строится wiki/code

| Что | Кто пишет | Источник |
|-----|-----------|----------|
| сигнатуры, пакеты, связи пакетов, тесты | tree-sitter | исходный код Go |
| API: gRPC, HTTP-привязки, сообщения, CRD | парсеры | `.proto`, YAML CRD |
| метрики, конфигурация чарта | парсеры | вызовы `prometheus.New*`, `values.yaml` |
| CHANGELOG | git | merge-коммиты между тегами |
| обзор компонента, описания без комментария | LLM | факты выше и фрагменты кода |

Правила для текста LLM:

1. LLM вызывается через OpenAI-совместимый API: `openai.base_url`, модель `docs_llm.model` (например, Qwen или DeepSeek на внутреннем шлюзе).
2. LLM получает только факты парсера и фрагменты кода. Строки, похожие на секрет, скрипт заменяет заглушкой до отправки.
3. Каждое имя в обратных кавычках в ответе должно быть в фактах парсера. Предложение с другим именем скрипт удаляет.
4. Пункт обзора без ссылки на код скрипт удаляет. Текст с email, телефоном или секретом скрипт удаляет.
5. Страница с текстом LLM имеет поле `llm: <модель>` во frontmatter и пометку «(LLM)» у каждого описания.
6. Ответы кэшируются по хэшу запроса (`docs_llm.cache_dir`). Неизменённый код не вызывает модель повторно.
7. Без ключа, при отказе API или после `docs_llm.max_calls` вызовов генератор пишет только факты. Job не падает.

## 6. Генерация в CI

| Событие | Откуда | Job | Результат |
|---------|--------|-----|-----------|
| Тег компонента | `templates/component-ci/wiki-docs.gitlab-ci.yml` | `component-docs` | `wiki/code/<компонент>/` |
| Тег репозитория чартов | `templates/charts-ci/wiki-release.gitlab-ci.yml` | `release-docs` | `wiki/code/releases/<тег>.md`, `config.md`, git-тег wiki |
| Merge `change/<KEY>` в master-spec | `templates/master-spec/.gitlab-ci.yml` | `changes-sync` | `wiki/changes/<KEY>.md` |
| Расписание | расписание CI ai-first | `changes-sync` | сверка страниц изменений по Jira |

1. Все job записи используют `resource_group: wiki-writer`. GitLab выполняет их по одному, конфликтов записи нет.
2. Job делает коммит в `main` напрямую. MR для сгенерированного содержания не нужен: оно получено из проверенных источников.
3. `code_docs.py` не перезаписывает документацию более новой версии старым тегом.
4. `release_docs.py` генерирует компонент, только если тег в релизе новее, чем в wiki: так закрывается пропущенный триггер.
5. Перед коммитом job запускает `wiki_lint.py`.

Если чарт не описан в `components.toml`, генерация релиза завершается ошибкой. Компонент без документации в релиз не проходит.

## 7. Зеркало Confluence

Каждая страница в `wiki/l2/` и `wiki/l3/` начинается с frontmatter:

```
---
title: Потеря кворума etcd
components: [etcd-backup]
url: https://confluence.example.com/pages/12345
confluence_id: 12345
confluence_version: 17
synced: 2026-10-21
---
```

- Поле `components` заполняется по меткам Confluence `component-<имя>`. Ставь такие метки на страницы.
- Страница L3 не ссылается на `l2/` и `code/`.
- Синхронизация обезличивает текст и проверяет секреты через `wiki_lint.py`.
