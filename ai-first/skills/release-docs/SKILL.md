# release-docs

Скил строит раздел Code wiki для релиза платформы.

## Запуск

```bash
git -C <путь_к_чартам> checkout <тег>
python scripts/release_docs.py <путь_к_чартам> <тег> --repos-dir .repos
```

| Параметр | Значение |
|----------|----------|
| `--previous` | предыдущий релиз; по умолчанию ближайший тег до текущего |
| `--repos-dir` | каталог для клонов компонентов; CI кэширует его |
| `--all` | перегенерировать все компоненты и модули |

## Что делает скрипт

1. Проверяет, что каждый чарт описан в `wiki/code/components.toml`.
2. Читает версию чарта и тег образа каждого компонента. Сравнивает их с предыдущим релизом.
3. Пишет `config.md` для всех компонентов.
4. Для каждого компонента и модуля даёт ссылку на документацию версии из релиза:
   - тег совпадает с последним в wiki — ссылка на текущую страницу;
   - тег старше — ссылка на коммит wiki, где эта версия была сгенерирована;
   - тег новее — генерирует документацию (пропущенный триггер `code-docs`).
5. Пишет `wiki/code/releases/<тег>.md`, обновляет `wiki/index.md` и `wiki/log.md`.

## Результат

Код 0 — документация записана. Код 1 — ошибка реестра или репозитория; скрипт выводит причину и ничего не пишет.

После запуска выполни `python scripts/wiki_lint.py`.
